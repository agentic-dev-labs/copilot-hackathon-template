# Visual Brief Design

Use a clear editorial layout, not a dashboard of nested cards. Prefer white surfaces with dark
ink, a restrained rose accent, and a distinct comparison colour for a second data series.
Use available local fonts with a serif heading and a readable sans-serif body. No font downloads
are required. Keep text large enough to read on a projector and allow wrapping on a narrow screen.

Use CSS variables for colours and consistent spacing. Source notes must remain readable and
must not overlap charts. Do not decorate with gradients, floating blobs, or meaningless KPIs.
Use a report cover only if reuse rights are established; an original chart is a useful visual asset.
Do not imply the student's briefing is an official company or Microsoft publication.

Each slide should have one dominant visual: a chart, timeline, diagram, or a small set of facts.
Prefer horizontal bars with a zero baseline and visible numeric labels. Do not compare annual
and interim totals on the same axis or show missing observations as zero. A caption states the
unit, source, and whether a number is reported or calculated. Make hover information available
on keyboard focus too. Add a data table so the visual is inspectable without colour or a mouse.

Navigation must work at the first and last slides, with a visible focus indicator and accessible
names. Support arrow keys outside editable fields. Print styles reveal all slides and sources.
Use responsive max-widths and aspect ratios rather than text that scales with viewport width.
Show all content when JavaScript is unavailable; JavaScript progressively enhances navigation.

For the afternoon notes/favourites extension, demonstrate an empty state, input validation,
safe text rendering, removal, reload persistence, and a storage-error message. A working useful
control is preferable to several decorative widgets. Let the learner choose the final appearance.
